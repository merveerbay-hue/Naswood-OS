# Event Catalog

**Project:** Naswood OS  
**Document:** Event Catalog  
**Version:** 1.0  
**Status:** Active Development

---

# 1. Purpose

This document defines every business event generated within Naswood OS.

Events represent completed business actions.

Events are immutable.

Events provide the communication layer between independent system modules.

Every event is permanently stored and forms part of the complete production history.

---

# 2. Event Philosophy

Naswood OS follows an Event-Driven Architecture.

Business modules do not communicate by directly modifying each other's data.

Instead, every completed business action generates a domain event.

Example

Material Produced

↓

MaterialProduced Event

↓

Inventory Engine updates stock

↓

Traceability Engine updates genealogy

↓

Quality Engine waits for inspection

↓

Dashboard updates production

↓

AI analyzes production

# 21. Business Rules

- Every completed business action generates an event.
- Events are immutable.
- Events cannot be deleted.
- Events must contain timestamps.
- Every event must be linked to the responsible user or system.
- Material-related events must reference Material ID.
- Production events must reference Work Order.
- Machine events must reference Machine ID.
- Quality events must reference Quality Event ID.
- Event history forms the official production history.
